# Цифровой детектив + Supabase

## Что добавлено
- Ввод имени/псевдонима участника.
- Сохранение результата в облачную таблицу Supabase.
- Рейтинг до 20 лучших результатов с датой и категорией.
- SQL-ограничения и Row Level Security (RLS).

## 1. Создай проект
1. Открой https://supabase.com/ и войди в аккаунт.
2. Нажми New project, выбери организацию, задай имя и пароль базы данных.
3. Дождись создания проекта.

## 2. Создай таблицу
1. Открой SQL Editor -> New query.
2. Открой файл `supabase_schema.sql`, скопируй весь код и вставь в редактор.
3. Нажми Run. Таблица `test_results` появится в Table Editor.

## 3. Получи URL и публичный ключ
В настройках проекта найди Project URL и anon / publishable key (раздел API Keys или Connect).

## 4. Подключи сайт
Открой `index.html` в редакторе и найди:
```js
const SUPABASE_URL = "ВСТАВЬТЕ_URL_ПРОЕКТА";
const SUPABASE_ANON_KEY = "ВСТАВЬТЕ_ANON_ИЛИ_PUBLISHABLE_KEY";
```
Замени текст внутри кавычек своими значениями. URL выглядит примерно так: `https://abcdefgh.supabase.co`.

ВАЖНО: не вставляй `service_role`, `secret` или secret key в HTML/JavaScript. Используй только anon/publishable key. Доступ ограничен RLS-политиками.

## 5. Запусти сайт
Для ES-модулей открой папку через локальный сервер, например VS Code + расширение Live Server, или размести на хостинге. Интернет нужен для связи с Supabase.

После прохождения результат появится в Table Editor -> test_results. Кнопка «Рейтинг участников» загрузит топ-20 результатов.

## Поля таблицы
`participant_name` — имя/псевдоним; `correct_answers` — правильные ответы; `total_questions` — число вопросов; `percentage` — процент; `result_category` — категория; `created_at` — дата и время.

## Объяснение для преподавателя
Вопросы и правильные ответы хранятся в массиве JavaScript. Выбранные варианты находятся в `selectedAnswers`. После завершения теста скрипт вычисляет результат и отправляет в Supabase только итоговые данные через `insert()`. Рейтинг загружается через `select()`.

В этой учебной версии правильные ответы находятся в браузере, поэтому результат можно подделать через инструменты разработчика. Для реального сервиса нужна серверная проверка ответов, авторизация и защита от спама. RLS ограничивает анонимный доступ операциями INSERT и SELECT.
